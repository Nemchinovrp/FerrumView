# FerrumView

Просмотр HLS-потоков камер в браузере.

## Запуск в Docker (в том числе Windows)

Установите и запустите Docker Desktop; на Windows используйте Linux containers.
В папке проекта должны лежать `streams.txt`, `dsi-cameras.txt` и `.dsi.env`.
Перенесите свои текущие файлы с камерами и cookie; для неиспользуемого списка
можно создать пустой файл. Они подключаются только при запуске и не входят в образ.

В терминале из папки проекта:

```sh
docker compose up -d --build
```

Откройте http://localhost:6523. Rust, FFmpeg с OpenSSL и curl устанавливаются
внутри образа автоматически. Первая сборка длительная: компилируются FFmpeg
и приложение. HTML и TLS-конфигурация встроены в приложение; режим `--inspect`
также сохранён. Образ собирается под архитектуру машины Docker.
Если порт 6523 занят обычным запуском FerrumView, сначала остановите его.

```sh
docker compose logs --tail=100 -f
docker compose down
```

Первая команда показывает логи, вторая останавливает контейнер.
После изменения списков камер обновите страницу. После замены файлов редактором
при необходимости выполните `docker compose up -d --force-recreate`, чтобы
обновить файловые подключения. После изменения исходного кода повторите команду
запуска с `--build`.

В контейнере `FERRUMVIEW_BIND=0.0.0.0:6523`; Compose публикует порт на всех
сетевых интерфейсах хоста. С другого компьютера открывайте `http://IP_UBUNTU:6523`
(адрес виртуальной машины, а не Proxmox). После изменения публикации порта
выполните `docker compose up -d --force-recreate`; пересборка не требуется.
Если доступ блокирует firewall Ubuntu или Proxmox, разрешите TCP 6523 из своей
локальной сети. У приложения нет авторизации: доступ из интернета организуйте
через VPN. При обычном запуске адрес остаётся `127.0.0.1:6523`.

## Запуск

Проверено с Rust 1.92.0 и установленными системными библиотеками FFmpeg.

```sh
cargo +1.92.0 run -- 'https://example.com/index.m3u8?token=...'
```

Откройте http://127.0.0.1:6523. Все камеры из списка воспроизводятся одновременно; дополнительный URL можно ввести вручную.
Ссылку с `&` или `#` передавайте в кавычках. Фрагмент после `#` плеер удаляет.
URL из аргумента не сохраняется в файлах или браузерном хранилище.

Axum отдаёт страницу; камеры из файлов передаются браузеру через локальный FFmpeg.
Плеер использует hls.js с CDN jsDelivr (нужен интернет); если он недоступен,
используется встроенная поддержка HLS браузера. Сервер камеры должен разрешать CORS
для плейлистов, сегментов и ключей при добавлении прямого URL через форму.
Плеер показывает состояние, поддерживает переподключение, звук и полный экран.
Сервер слушает только локальный адрес. Остановка: Ctrl+C.

## Список камер

Добавляйте камеры в `streams.txt` в рабочей директории запуска (корень проекта):

```text
Двор | https://example.com/yard/index.m3u8?token=...
Парковка | https://example.com/parking/index.m3u8
```

Пустые строки и комментарии, начинающиеся с `#`, пропускаются.
Если `streams.txt` отсутствует, читается `stream.txt`.
Список перечитывается при обновлении страницы — пересборка не нужна.
На странице сетка из трёх камер в ряд, на узких экранах — две или одна.
У каждой камеры отдельный плеер, статус и кнопка переподключения.
Запуск списка: `cargo +1.92.0 run --offline`.

При ошибке потока или отсутствии продвижения видео 30 секунд (45 при старте) камера автоматически
переподключается. Пауза между попытками: 3, 6, 12, 24, затем 30 секунд.
После 30 секунд стабильного воспроизведения задержка сбрасывается.
Плеер показывает только прямой эфир, без полосы перемотки и кнопки паузы.
Звук и полный экран управляются кнопками на карточке. При запрете автозапуска
появляется кнопка «Смотреть онлайн». При возвращении на вкладку и заметном
отставании плеер переходит к актуальному моменту потока. HLS требует небольшого
буфера, поэтому задержка в несколько секунд возможна; записи архива нет.

Камеры из `streams.txt` (или `stream.txt`) используют ту же серверную передачу,
что и DSI: FFmpeg последовательно получает поток и сохраняет скользящий список
из 12 сегментов. Перед началом показа плеер накапливает минимум 6 секунд видео.
Это добавляет задержку и время первого запуска, но позволяет переживать короткие
задержки источника. Видео не перекодируется; звук преобразуется в AAC.
Проверка TLS остаётся включённой; специальные заголовки и OpenSSL-конфигурация
DSI не применяются к другим провайдерам. Для всех камер из файлов нужен FFmpeg.

## Камеры dsi.ru

Ссылки dsi.ru из списка автоматически заменяются локальными `/relay/...` URL.
FFmpeg (команда `ffmpeg` в PATH, сборка с OpenSSL) получает HLS и создаёт
короткий локальный HLS-плейлист. Видео копируется без перекодирования,
аудио при наличии преобразуется в AAC. Камеры других провайдеров из файлов
также передаются через FFmpeg, без настроек авторизации DSI.

`config/dsi-openssl.cnf` задаёт TLS 1.2+ и `DEFAULT:@SECLEVEL=1` исключительно
для дочерних FFmpeg-процессов DSI через `OPENSSL_CONF`. Системный OpenSSL и
настройки браузера не меняются. Проверка сертификата включена (`tls_verify=1`).

Ретрансляция запускается при запросе плеера и останавливается через 90 секунд
без запросов видео. Завершившийся процесс или поток без обновления плейлиста
45 секунд автоматически перезапускается. Сегменты хранятся во временной
директории и удаляются при штатной остановке; старые сегменты удаляет FFmpeg.
Добавленные вручную на странице URL загружаются напрямую: DSI добавляйте в файл.

DSI-подключения отправляют User-Agent из рабочего профиля go2rtc,
`Origin: https://video.dsi.ru` и `Referer: https://video.dsi.ru/`.
Эти заголовки применяются только к DSI-ретрансляции.

### Автоматическое получение актуальных ссылок

В `dsi-cameras.txt` указывайте название и постоянный номер камеры через `|` (названия могут совпадать):

```text
Подъезд 132 | 18830
Подъезд 132 | 18838
```

Номер берётся из адреса страницы `/account/camera/18830/view.html`, а не из временного HLS-адреса.
Старый формат с полной ссылкой страницы также поддерживается.
Если этот файл непустой, его камеры заменяют старые DSI-ссылки из `streams.txt`.
Камеры других провайдеров остаются в сетке. После изменения списка обновите страницу.

В `.dsi.env` сохраните `DSI_COOKIE='значение Cookie из запроса url.html'`.
Файл исключён из Git. Ограничьте доступ командой `chmod 600 .dsi.env`.
Сессионный cookie передаётся только API `https://video.dsi.ru` через stdin curl;
он не попадает в аргументы процесса, логи и ответы браузеру. Дополнительно
к FFmpeg требуется `curl` с рабочим системным набором CA-сертификатов.

При запуске камеры FerrumView получает свежую ссылку через API DSI.
При обрыве или зависании видео он повторно запрашивает адрес и запускает FFmpeg.
Повторные попытки идут с задержкой от 3 до 30 секунд, одновременно выполняется
не более трёх запросов к API. Обновление cookie подхватывается при следующей
попытке без перезапуска приложения. Если сессия истекла или доступ к камере
запрещён, сообщение появляется на её карточке. Повторный вход на сайт и
обновление cookie выполняются вручную; скрипт refresh-dsi.sh и cron не нужны.
